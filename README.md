# Практикум 1. Типы, ветвления, циклы

Репозиторий: https://github.com/ivashka27/cpp-lab-01

Пара на 2–3 часа к первой лекции по C++. В репозитории уже лежит шаблон: сигнатуры функций, каркас программ и тесты. Нужно заполнить места с `TODO`, проверить себя командой `make test` и открыть pull request.

Новых тем сверх лекции нет. Хватает того, что уже разобрано:

- `#include`, `std::cin`, `std::cout`;
- `int`, `double`, `long long`, `bool`, `std::string`;
- `if` / `else`, `for`;
- функции, которые получают копии аргументов и возвращают результат.

Не нужны указатели, массивы, `std::vector`, классы и `using namespace std`. В заголовках имена стандартной библиотеки написаны как `std::...`.

## Сборка

Собрать проект — значит превратить `.cpp` в программу и запустить тесты. В редакторе нет кнопки Build: команда вводится в терминале. Откройте терминал в VS Code (Terminal → New Terminal) или обычный терминал и перейдите в папку, где лежит `Makefile`.

```bash
git clone https://github.com/ivashka27/cpp-lab-01.git
cd cpp-lab-01
ls Makefile
```

`ls Makefile` печатает имя файла. Если пишет, что файла нет, терминал открыт не в той папке: ищите каталог `cpp-lab-01` и зайдите в него через `cd`.

### Поставить компилятор

Проверка, что компилятор уже есть:

```bash
g++ --version
```

Должна появиться строка вроде `g++ (GCC) ...`. Если команда не найдена, поставьте компилятор и откройте терминал заново.

Linux:

```bash
sudo apt update
sudo apt install -y build-essential
```

macOS:

```bash
xcode-select --install
```

Windows: обычные PowerShell и cmd не подходят. Поставьте [MSYS2](https://www.msys2.org/), откройте приложение **MSYS2 UCRT64** и выполните:

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gcc make
```

В VS Code на Windows выберите этот же терминал: Terminal → Select Default Profile → UCRT64. Иначе редактор открыт, а `g++` в его терминале по-прежнему нет.

В CLion зелёная кнопка сборки для этого практикума не используется. Нужен терминал внизу окна и те же команды.

### Запустить сборку и тесты

Из папки с `Makefile`:

```bash
make test
```

Если `make` не найден, а `g++ --version` уже печатает версию:

```bash
bash scripts/test.sh
```

Одна часть, а не все четыре:

```bash
make test-types
make test-branches
make test-loops
make test-journal
```

Первый запуск обязан закончиться словом `FAILED`. Это собранный проект с пустыми функциями, а не сломанная установка. Смотрите на строку перед списком проверок.

Собралось, тесты ещё не проходят — так и нужно, пока `TODO` пустые:

```text
== check_types ==
FAIL DivideInts(5, 2) == 2
...
FAIL check_types
FAILED
```

Не собралось — чинить компилятор или синтаксис, тесты ещё не запускались:

```text
== check_types ==
FAIL check_types: compile
```

`g++: command not found` значит, что компилятор не установлен или открыт не тот терминал. `make: *** No targets specified` или `No such file or directory` у `Makefile` значит, что команда запущена не из корня репозитория.

Собрать первое задание руками, без `make`:

```bash
mkdir -p build
g++ -std=c++20 -Wall -Wextra -o build/check_types \
  tasks/01_types/types.cpp tasks/01_types/check.cpp
./build/check_types
```

`g++` читает два исходника и записывает программу в `build/check_types`. Вторая команда её запускает. Каталог `build/` в git не кладётся: это результат сборки, не решение.

## Задание 1. Типы

Файл: `tasks/01_types/types.cpp`.

`DivideInts` — обычное целочисленное деление. Для отрицательных C++ округляет к нулю: `-5 / 2` равно `-2`. На ноль в тестах не делят.

`DivideAsDouble` — то же деление, но результат дробный. `5` и `2` дают `2.5`. Деление двух `int` этого не сделает: сначала один из аргументов нужно привести к `double`.

`FitsInInt` — `true`, если `long long` помещается в `int`, включая обе границы. Границы смотрят так:

```cpp
#include <limits>

std::numeric_limits<int>::min()
std::numeric_limits<int>::max()
```

`SumAsLongLong` — сумма двух `int` в типе `long long`. Сложение `2000000000 + 2000000000` не помещается в `int`. Если сложить числа как `int` и только потом привести результат к `long long`, большая сумма уже испорчена. Приводить к `long long` нужно до сложения.

## Задание 2. Ветвления

Файл: `tasks/02_branches/labels.cpp`.

`SignLabel`:

- отрицательное → `negative`
- ноль → `zero`
- положительное → `positive`

`ParityLabel`: `even` или `odd`. Ноль чётный. Чётность проверяют условием `value % 2 == 0`. Сравнение остатка с `1` ломается на отрицательных: остаток `-3 / 2` в C++ равен `-1`, а не `1`. `-4` — чётное.

`GradeLabel` для балла:

| Балл | Строка |
| --- | --- |
| вне `0..100` | `invalid` |
| `0..59` | `fail` |
| `60..74` | `pass` |
| `75..89` | `good` |
| `90..100` | `excellent` |

Границы включительны: `59` — это `fail`, `60` — `pass`, `89` — `good`, `90` — `excellent`.

## Задание 3. Цикл

Файл: `tasks/03_loops/main.cpp`.

Программа читает `n`, затем `n` целых. В тестах `n >= 0`. При `n == 0` чисел дальше нет. Формат печати уже написан, его менять не нужно. Нужно заполнить тело цикла.

Вывод:

```text
sum: <сумма>
min: <минимум или none>
max: <максимум или none>
positive: <сколько чисел строго больше нуля>
```

Ноль и отрицательные в `positive` не входят. Пока чисел не было, минимум и максимум — это `none`, а не `0`. Сумму копите в `long long`: три числа `1000000000` в `int` не влезают.

Пример. Вход:

```text
5
-2 0 4 -8 4
```

Выход:

```text
sum: -2
min: -8
max: 4
positive: 2
```

Пробел и перевод строки для `std::cin` — одно и то же.

## Задание 4. Журнал баллов

Файлы: `tasks/04_journal/journal.cpp` и `tasks/04_journal/main.cpp`.

Это одна программа. Сначала реализуйте функции: их отдельно гоняет `make test-journal` в начале протокола, ещё до проверки всей программы. Потом допишите две проверки и тело цикла в `main.cpp`. Чтение входа и печать отчёта в каркасе уже есть.

Вход:

```text
<имя из одного слова>
<n>
<балл 1>
...
<балл n>
```

Балл верный, если он от `0` до `100` включительно. Зачёт по баллу — это `>= 60`.

Функции:

- `IsValidScore` — балл внутри `0..100`;
- `AddToSum` — прибавить балл к сумме типа `long long`;
- `NextMin` / `NextMax` — новый минимум или максимум. Если `has_score == false`, старого значения ещё нет, верните сам балл;
- `NextPassed` — увеличить счётчик, если балл `>= 60`;
- `Average` — среднее. Делить как `double`. Сумма `2` и количество `3` дают примерно `0.666...`, не `0`. В `main` это печатается с двумя знаками;
- `Verdict` — строка итога. Условия проверяйте строго в этом порядке:
  1. `count == 0` → `empty`
  2. `passed != count` → `debt` (есть балл ниже 60)
  3. `min_score >= 90` → `excellent`
  4. иначе → `ok`

Порядок важен. Журнал из баллов `90 90 50` — это `debt`, хотя минимум у части баллов высокий. Пустой журнал — `empty`, даже если в минимум случайно попало большое число.

В `main.cpp` осталось сделать три вещи:

1. Если `n < 0`, напечатать ровно `invalid count` и вернуть `1`. Отчёт не печатать.
2. Если балл не прошёл `IsValidScore`, напечатать ровно `invalid score` и вернуть `1`. Отчёт не печатать.
3. В цикле обновить сумму, минимум, максимум и число зачётов. `NextMin` и `NextMax` вызывайте до того, как поставите `has_score = true`: на первом балле старого минимума ещё нет.

`failed` считать не надо отдельной функцией: в каркасе это `count - passed`.

Пример с долгом. Вход:

```text
Ivan
4
100
59
90
75
```

Выход:

```text
name: Ivan
count: 4
sum: 324
average: 81.00
min: 59
max: 100
passed: 3
failed: 1
verdict: debt
```

Пустой журнал. Вход:

```text
Leo
0
```

Выход:

```text
name: Leo
count: 0
sum: 0
average: n/a
min: n/a
max: n/a
passed: 0
failed: 0
verdict: empty
```

Ошибка. Вход:

```text
Ann
2
40
120
```

Выход — одна строка `invalid score`, код возврата `1`.

Тесты дополнительно проверяют границу `89` / `90`, балл `60` рядом с `59`, округление `2 / 3` до `0.67`, отрицательный балл и отрицательное `n`.

## Как сдать

Репозиторий общий. Своё решение приносят pull request-ом, в `main` напрямую не пушат.

1. На GitHub нажмите Fork.
2. Склонируйте свой форк и перейдите в каталог:

```bash
git clone <url-вашего-форка>
cd cpp-lab-01
git checkout -b lab01/<ваш-логин>
```

3. Когда `make test` печатает `ALL OK`, зафиксируйте решение. Если пара уже закончилась, сдавайте то, что готово, и отметьте это в описании pull request.

```bash
git status
git add tasks/01_types/types.cpp tasks/02_branches/labels.cpp tasks/03_loops/main.cpp tasks/04_journal/journal.cpp tasks/04_journal/main.cpp
git commit -m "Solve lab 01"
git push -u origin lab01/<ваш-логин>
```

4. На GitHub откройте pull request в [ivashka27/cpp-lab-01](https://github.com/ivashka27/cpp-lab-01), ветка `main`. В описании напишите фамилию и имя. Шаблон описания подставится сам.

`git commit` без `git add` ничего не сохранит. `git commit` без `git push` ещё не сдача: пока ветка не на GitHub, pull request открыть нельзя.

Чужие pull request не открывайте, пока не сдадите свой.
